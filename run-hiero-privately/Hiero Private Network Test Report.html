1. Summary

We built the network twice: once with the runbook's scripts and once with Hedera's Node Management Tools. We ran a fixed suite of 24 functional checks against it four times. Every run passed all 24. The mirror node imported every result correctly (7 of 7 checks). The treasury key check, consensus state hashes and a single-node outage test all behaved as expected.

The long-running test found one serious operational defect. After 3.8 days, the network built with Node Management Tools halted because event-stream files filled the 30 GB disks. No component raised an alert. The runbook now turns event streams off, sizes disks at 100 GB and lists the alerts to configure (section 7).

3. Method

The suite tests that the four nodes behave as one ledger, not only that each one answers requests:

  • Writes go to specific nodes. The transactions are spread across all four nodes, so each node must accept and gossip transactions.
  • Reads go to every node. Each read is sent to all four nodes separately, and the check passes only if all four give the same answer.
  • Values are checked exactly. Balances, sequence numbers, token supply and contract state must equal the expected values, not just exist.

The suite covers the four main Hiero services:

  • cryptocurrency: accounts and transfers;
  • consensus service: topics and messages;
  • token service: a fungible token;
  • smart contracts: Solidity on the EVM.

All transactions are signed by the treasury account 0.0.2 with the network's own treasury key. Separate scripts check the treasury key itself and the mirror node. Shell commands on each node check status and state hashes.

Why the functional suite is not enough on its own

Run A-1 passed all 24 checks while the network was misconfigured. The treasury public key had been written to bootstrap.properties, where the public documentation places it, but the node reads it only from application.properties. The network had therefore started with the publicly known development key.

The suite cannot see this, because it signs with whichever key controls the treasury. We re-created the network (run A-2) and added a dedicated key check (section 6). The runbook writes the key to the correct file and runs the key check as part of verification.

7. Long-running stability

The Node Management Tools build was left running with no load after testing. It was ACTIVE for 3.8 days, then stopped reaching consensus.

  1. Day 0, startAll 4 nodes started; ACTIVE about 50 seconds later.
  2. About 3 days 15 hoursNode 1's disk is full. It falls behind, and its attempt to copy state from a peer fails with No space left on device.
  3. 3 days 16 hours 29 minutesNode 1's container exits with code 203. Nothing restarts it: the Node Management Tools container policy is "no". The other 3 nodes carry on, as designed.
  4. 3 days 19 hours 54 minutesNode 3's disk is full. Its pre-consensus event writer fails, so it stops contributing.
  5. 9 seconds laterWith only 2 of 4 nodes healthy, below the two-thirds needed, the network stops reaching consensus. All running nodes report CHECKING ("Platform spent 3.8 d in ACTIVE").

Root cause

Event streaming (event.enableEventStreaming) is on by default in the consensus node. It writes one event file and one signature file every 5 seconds to /opt/hgcapp/eventsStreams, and nothing deletes them. On an idle network, this reached 18–19 GB and about 132,000 files per node in 3.8 days, roughly 5 GB per day. That filled the 29 GB root filesystem.

The other directories stayed small: saved states 1.5–1.7 GB, logs 1.1–1.2 GB (log files roll at a fixed size), record streams under 1 MB. The Hiero repository's own development configuration disables event streaming. The Node Management Tools default and Solo's configuration template both leave it enabled.

Detection

No component raised an alert:

  • the stopped container was not restarted;
  • the containers on the stalled nodes kept reporting "running";
  • neither Node Management Tools nor the node software ships a health check.

The failure showed only through the platform status metric and the node logs.

Mitigation in runbook v1.0

  • hiero-node.sh configure sets event.enableEventStreaming, false. The mirror node uses record streams, not event streams. Operators who need event streams can keep them with --keep-event-streams and must prune them.
  • Minimum disk raised to 100 GB per host.
  • A new state command shows state hashes and disk use per directory, and the runbook adds a check that the event-stream directory stays empty.
  • The runbook lists the minimum alerts: platform status, state-hash agreement, disk use and service restarts.
  • The runbook's systemd unit restarts a crashed node after 10 seconds.

The mitigation was checked on the test hosts but not yet through a full rebuild and a multi-day run. We recommend repeating the long-running test with runbook v1.0 before production use.

9. Not covered

These areas were outside the tests in this report:

  • software upgrades through a network freeze;
  • adding or removing a node after genesis;
  • backup and restore;
  • throughput and load testing;
  • client connections over TLS;
  • a multi-day run with the mirror node attached;
  • failure of two nodes at once (other than the incident in section 7).

Both deployments ran in a single cloud account and network, with the independent operators simulated by one team.

// Each write is sent to one specific node; every result is then read back from all four nodes
// and must be identical. Entity ids are saved to verify-ids.json for mirror-check.mjs.
//
//   HIERO_NODES="10.0.1.11:50211=0.0.3,10.0.1.12:50211=0.0.4,10.0.1.13:50211=0.0.5,10.0.1.14:50211=0.0.6" \
//   OPERATOR_KEY_DER=<genesis key, DER hex> node network-check.mjs
//
// Use the plaintext gRPC port (50211). The SDK assumes TLS on 50212 and 443.
import { writeFileSync } from "node:fs";
import {
  AccountInfoQuery, AccountCreateTransaction, AccountId, Client, ContractCallQuery, ContractCreateTransaction,
  ContractExecuteTransaction, ContractFunctionParameters, Hbar, PrivateKey, TokenCreateTransaction,
  TokenInfoQuery, TokenType, TopicCreateTransaction, TopicInfoQuery, TopicMessageSubmitTransaction,
  TransferTransaction,
} from "@hiero-ledger/sdk";
import solc from "solc";

const NOTE = "network verification";
const NODES = Object.fromEntries((process.env.HIERO_NODES ?? "").split(",").filter(Boolean).map((e) => e.split("=")));
if (Object.keys(NODES).length !== 4 || !process.env.OPERATOR_KEY_DER) {
  console.error("set HIERO_NODES (4 entries host:port=0.0.N) and OPERATOR_KEY_DER"); process.exit(2);
}
const nodeIds = Object.values(NODES).map((n) => AccountId.fromString(n));
const label = (id) => `node-${Number(id.toString().split(".")[2]) - 2} (${id})`;
const operatorKey = PrivateKey.fromStringDer(process.env.OPERATOR_KEY_DER);
const client = Client.forNetwork(NODES).setOperator("0.0.2", operatorKey);
client.setRequestTimeout(60_000);

const results = [];
const check = (name, ok, detail) => { results.push(ok); console.log(`${ok ? "PASS" : "FAIL"}  ${name}${detail ? "  — " + detail : ""}`); };
const t0 = Date.now();
const via = (tx, i) => tx.setNodeAccountIds([nodeIds[i]]);
async function readFromAll(name, fn) {
  const answers = [];
  for (const id of nodeIds) answers.push([label(id), String(await fn(id))]);
  const same = answers.every(([, a]) => a === answers[0][1]);
  check(`${name} — same answer from all 4 nodes`, same, same ? answers[0][1] : JSON.stringify(answers));
  return answers[0][1];
}

// 1. Treasury balance agrees on every node
await readFromAll("Treasury 0.0.2 balance", async (id) =>
  (await new AccountInfoQuery().setAccountId("0.0.2").setNodeAccountIds([id]).execute(client)).balance.toString());

// 2-5. Account create, transfer, balance
const userKey = PrivateKey.generateED25519();
let r = await (await via(new AccountCreateTransaction().setKeyWithoutAlias(userKey.publicKey).setInitialBalance(new Hbar(10)), 0).execute(client)).getReceipt(client);
const userId = r.accountId; check("Create account via node-1", r.status.toString() === "SUCCESS", `${userId}, 10 ℏ`);
r = await (await via(new TransferTransaction().addHbarTransfer("0.0.2", new Hbar(-5)).addHbarTransfer(userId, new Hbar(5)), 1).execute(client)).getReceipt(client);
check("Transfer 5 ℏ via node-2", r.status.toString() === "SUCCESS");
const bal = await readFromAll(`Balance of ${userId}`, async (id) => (await new AccountInfoQuery().setAccountId(userId).setNodeAccountIds([id]).execute(client)).balance.toString());
check("Balance is 15 ℏ", bal === "15 ℏ", bal);

// 6-11. Consensus service: topic and three messages
r = await (await via(new TopicCreateTransaction().setTopicMemo(NOTE), 2).execute(client)).getReceipt(client);
const topicId = r.topicId; check("Create topic via node-3", r.status.toString() === "SUCCESS", `${topicId}`);
for (let i = 1; i <= 3; i++) {
  r = await (await via(new TopicMessageSubmitTransaction().setTopicId(topicId).setMessage(`hello #${i}`), 3).execute(client)).getReceipt(client);

}
const seq = await readFromAll(`Topic ${topicId} sequence number`, async (id) => (await new TopicInfoQuery().setTopicId(topicId).setNodeAccountIds([id]).execute(client)).sequenceNumber.toString());

// 15-24. Smart contract service: compile, deploy, call from every node
const source = `// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;
contract Counter { uint256 public count; string public note; event Incremented(address indexed by, uint256 count);
  constructor(string memory n) { note = n; }
  function increment() external { count += 1; emit Incremented(msg.sender, count); } }`;
const out = JSON.parse(solc.compile(JSON.stringify({ language: "Solidity", sources: { "Counter.sol": { content: source } },
  settings: { evmVersion: "paris", optimizer: { enabled: true, runs: 200 }, outputSelection: { "*": { "*": ["evm.bytecode.object"] } } } })));
const bytecode = out.contracts["Counter.sol"].Counter.evm.bytecode.object;
check("Compile Counter.sol (solc " + solc.version().split("+")[0] + ")", bytecode.length > 0, `${bytecode.length / 2} bytes`);

const ctorArgs = new ContractFunctionParameters().addString(NOTE)._build();
r = await (await via(new ContractCreateTransaction().setBytecode(Buffer.concat([Buffer.from(bytecode, "hex"), Buffer.from(ctorArgs)])).setGas(300_000), 1).execute(client)).getReceipt(client);
const contractId = r.contractId; check("Deploy contract via node-2", r.status.toString() === "SUCCESS", `${contractId} (EVM 0x${contractId.toEvmAddress()})`);
for (let i = 0; i < 4; i++) {
  r = await (await via(new ContractExecuteTransaction().setContractId(contractId).setGas(100_000).setFunction("increment"), i).execute(client)).getReceipt(client);
  check(`increment() via ${label(nodeIds[i])}`, r.status.toString() === "SUCCESS");
}

check("count() is 4 (one increment per node)", count === "4", count);
